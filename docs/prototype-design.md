# Swapy 交互原型

## 已确认目标

用户要求简洁清晰、组件交互充分，并指定 Chrome/Edge 80+。后续交付改为 Docker 部署的 B/S 架构，取代桌面应用方案。本次是明确要求的交互原型，不实现正式文档适配器或压缩协议。

## 交付

- `prototype/index.html`：轻量、可点击、示例数据驱动，依赖本地存放。
- React 17 + Ant Design 4 UMD 提供成熟交互组件；不需要构建工具。
- 三种结构可切换：工作台 A、流程向导 B、任务中心 C。默认 A。
- 可创建扫描/脱敏/还原演示任务，查看文件索引、失败明细和映射；可导出演示 HTML 报告、HTML/JSON 密码本。
- 词库管理展示新增、弃用、版本检查及同步的原型流程。密码包导入仅演示接口元数据，不伪装为正式协议。
- 页面始终标明演示状态，所有持久化在内存中；刷新恢复示例。

## 界面方向

操作型界面，采用在办公环境可读的浅色表面、深色文字和单一蓝绿色操作色。主操作明确，文件列表作为主体，设置按需展开，避免统计卡片占据首页。

候选结构：文件浏览器、分步表单、记录笔记、批处理工作台、双栏比对、路径导航、报告目录。工具选定索引 4（1372575e），默认构建批处理工作台；原型保留流程向导与任务中心供实际比较。

## Docker / B/S 边界

原型仅提供静态浏览器客户端，以 Docker Compose 运行静态服务。正式版本需由后端执行扫描、文件转换、任务登记、词库同步和密码包处理；浏览器以文件上传或服务端挂载目录选取输入。浏览器不能将用户输入的本机路径直接当作服务器可读目录。

## 验证

检查桌面与窄屏布局、任务创建/进度/取消、筛选和文件详情、失败报告、密码本导出、版本过低提示及词库同步。当前浏览器检查不等同于在 Chrome 80 实机完成兼容认证。

# Swapy Java / SQLite 开发设计

状态：用户授权“完善审核设计后就开始开发”，按本稿推荐完成工程审核后直接实施，无需再次逐项确认。日期：2026-11-23。

2026-11-24 独立代码审核后的收紧约定：原文提取缓存只放受控 data/work，不能出现在任务结果树；文件READY意图、DONE结果、问题与映射使用记录必须同一SQLite事务提交；全部有效文件先在私有暂存树准备，最后一次原子目录移动发布整个files树，避免SQL半组可见。恢复先对账并发布已提交子集，再为中断任务生成报告并清理原文缓存。无命中文档字节原样复制。SQL无法完整绑定字段的语句整组明确跳过，不能仅凭语法可解析认定一致。

Git手工导入高版本全历史快照时，可以建立不可变checkpoint标签，显式记录parentVersion及parentHash，不伪造缺失旧版本标签；消费者按标签链验证并原子导入完整历史。此约定使离线词库导入与后续Git发布可衔接，ID不可变、弃用不复活、lineage一致和版本不降级仍强制执行。

本稿是当前架构依据，替代旧后端方案中的 Python、PostgreSQL、多容器强制部署、SKIP LOCKED 和数据库租约实现。业务依据为 [需求规格](../../requirements-v1.1.md)。旧 [后端设计](2026-11-23-swapy-backend-design.md) 的匹配算法、区域矩阵、包协议和异常语义继续有效，冲突时本稿与最新用户决定优先。

## 1. 交付与取舍

采用 Java 17、Spring Boot 4.2.0、SQLite JDBC 3.54.1.0；版本已核对 Maven Central。单个可执行 JAR 提供静态页面和 API，默认监听 127.0.0.1:4175。Windows 启动脚本优先使用随包 runtime，再使用 JAVA_HOME / PATH；可以打包精简运行时。SQLite 位于本机 data 目录，原件和输出可位于本机或服务账号可访问的共享盘。不把数据库放共享盘。

SQLite 适用于单实例服务；WAL + synchronous=FULL + foreign_keys=ON + busy_timeout，所有业务写事务经单写入锁串行提交，读取独立连接。四路文档 IO/CPU 并行，不在事务中解析文档。SQLite 只有一个写入者，[官方约束](https://www.sqlite.org/whentouse.html)；WAL 不放网络文件系统，[官方说明](https://www.sqlite.org/wal.html)。通过锁文件阻止两个服务实例共用同一 data 目录，后续多实例才考虑 PostgreSQL。

与旧方案相比，Java 避免部署 Python 与数据库服务；文档工具链需要重新适配。SQLite 仍保留任务历史和持久工作项，不以纯内存队列承担续扫。

## 2. 选择目录与访问边界

本机 Java 服务直接持有文件访问能力。默认使用网页内文件浏览器选择已登记根目录的文件／目录，选择后扫描立即开始；执行页不展示普通文件清单。另提供同机 Java 原生选择器能力，只返回 root ID 和相对路径。原生选择仅允许本机连接调用，且须由交互启动器显式启用并确认调用浏览器与服务属于同一用户桌面会话；Windows服务、RDP会话无法证明对应关系或无图形会话时均回退网页选择器，不仅凭loopback或非headless判断。由此无需安装独立桥接组件，不上传原件。

部署 roots 配置来源为启动参数或环境变量，不增加服务设置页。未配置时仅登记当前工作目录和用户主目录，输出使用 data/tasks；UI 返回根目录显示名和 ID。输入引用 `{rootId,path}` 只允许根内相对路径。逐级拒绝符号链接、目录联接和越界路径，处理前再次验证；输出必须为允许输出根内的新 task ID 目录。默认排除输出、data、内部工作目录。

默认仅本机浏览器访问。检查 Host 与 Origin、拒绝跨域写入；网页 API 的变更请求使用启动时随机令牌，静态同源页面获取后带请求头。任意远端电脑的独立本地盘仍不可直接访问；共享盘必须先可由 Java 服务读取。

## 3. 数据与事务

显式 SQL 迁移，使用 JDBC，不引入 JPA 对 SQLite 的方言猜测。表：metadata、word_entries、word_events、catalog_releases、tasks、work_items、work_groups、group_members、task_mappings、path_mappings、issues、artifacts、import_batches。SQL组成员、组代数和就绪状态持久记录，不能仅靠内存计数。任务 ID 覆盖扫描、脱敏、还原统一主键；输入引用、配置、阶段、计数、版本、是否由导入产生独立登记。

词条采用 S_/R_ + 随机 UUID，新建时数据库 ID 主键确保双库共同唯一。已发布内容不可变，修改产生新 ID、旧 ID 追加弃用事件。统一权威发布源维护递增版本和 lineage；任务不能因为词库更新改动已分配映射。手工导入验证全历史、同 ID 内容、不可复活与版本链，整批事务提交；导出包含双库与弃用历史。任务包不同任务类型的 ID 冲突也检查。

Git 同步从部署配置指定仓库的不可变发布清单读取；权威端发布使用 outbox/暂存文件/tag 后登记，失败重试不推进有效版本。不自动 push 远端。未配置仓库时手工词库导入导出可独立使用，不编造同步成功。

## 4. 固定四路与扫描断点

单实例协调器管理全局固定 4 个执行槽，任务轮转公平分配。所有文件发现、提取、归档展开、改写和格式转换共享预算；子进程不得额外占一套四路池。无 parallelism 配置接口。

扫描状态 CREATED / DISCOVERING / PROCESSING / PAUSING / PAUSED / FINALIZING / SUCCEEDED / PARTIAL / FAILED；脱敏、还原增加 PREFLIGHT / RESOLVING / INTERRUPTED。暂停停止新工作，当前文件提交后到 PAUSED。浏览器关闭不会暂停服务任务。

扫描以“已完成文件”为断点。任务与发现文件清单持久保存；目录发现完成前重启则重新枚举并以唯一相对路径去重。重启把未完成工作项重新入队，已完成项验证源大小、时间与摘要后跳过，已变化项失效重扫。用户主动暂停的任务不自动继续；其他被中断扫描可恢复。未提交的半个文件重新处理，不保存解析器内存。

单文件结果、issues 和计数同事务提交；删除旧结果及回退计数再重扫必须原子完成，不能重复词频。归档按外层指纹和完整成员链定位，固实包重启可顺序重解压但不重复记账。仅显示异常，发现时 totalKnown=false，处理阶段按逻辑叶级文档计数。

脱敏／还原重启标记 INTERRUPTED，已完成文件和映射保留，重新执行新建任务，不跨重启续跑。

## 5. 匹配、映射与版本

沿用旧设计 §6：中文子串，英文 ASCII 大小写不敏感且受字母／数字／下划线词边界保护，最长重叠优先；属性优先级手填>词典>规则，语义类型不得变。任务内源与目标一对一，每任务随机分配。

先提取全任务完整文本和名称建立避重索引，再分配候选。建议降低业务实体关联性而非使用生僻词。无法完整提取的文档整文件退出改写集合并报告；避重仅能对实际完整处理集合保证。可提取但不能改写的区域仍参与避重。候选耗尽跳词，输出部分脱敏。

英文基础候选须有相同数量 ASCII 字母，逐字母传递大小写，实现 A/B 和名称中每处写法可逆。目标之间不包含不足以证明可逆，必须按旧设计 §6.2.1 在整任务虚拟输出上枚举所有潜在重叠命中并核对预期替换区间；失败重选，耗尽跳词。已写回文件二次抽取校验；后续新增映射同样复验已提交输出的兼容性。

A 默认，B 可选，单任务统一模式。A 使用任务注册 ID 与映射序号完整识别，先识别 A 再在不重叠区兼容 B；损坏片段不猜测。B 全部替换，包括用户后写同名词。还原不以文件 hash 相等为前提。完整 JSON 自带映射可离线还原；任务包依赖本地统一发布词库版本下限。

已完成文件不因库更新自动重扫；新分配可采用更新词条，但旧映射稳定。requiredVersion 是实际引用词条 introducedVersion 最大值，局部规则生成目标带完整结果，不假造发布 ID。

## 6. 格式实现与资源边界

统一 DocumentAdapter 接口：probe、extract、rewrite、validate；extract 返回可匹配区间与结构定位，不能用全部字符串替换破坏结构。

| 格式 | Java 实现与约束 |
| --- | --- |
| TXT/LOG/CSV/MD | 编码与换行保留；CSV 单元格；MD 正文、代码与 URL 均处理，保留语法 |
| JSON/XML | 词法跨度／安全 XML 解析，保护键或标签及属性名，仅改约定字符串数据 |
| YAML/TOML/INI/HTML | 保留 token 的适配器，字符串值、文本、约定属性与注释；结构和脚本样式保护；不能安全处理报告 |
| SQL | JSqlParser + 原 token 定位 + 方言验证；字符串、注释、字段定义与引用；保护表名和关键字。全部 SQL 为保守一致性组，统一预检／暂存验证后整组可见；无法绑定的字段组全部保留报告，不允许只改定义 |
| DOCX | Apache POI/OOXML；正文、表格、页眉页脚、脚注尾注、批注、文本框；跨 run 匹配后回映射，不重建整段导致格式丢失 |
| DOC/RTF/ODT | LibreOffice 独立 profile、超时受控子进程原格式写回；不可用明确报告，交付环境需安装或随发行构建提供此依赖 |
| PDF | Apache PDFBox 提取与内容流文本操作；真正移除原文本操作后写入，离线字体，验证文本不残留和版式。定位／字体／图形交叠无法保证时跳过并报告，不做 OCR 或白框遮盖冒充脱敏 |
| ZIP/7Z/RAR | 仅扫描，Commons Compress + RAR 适配器；加密不解密；RAR 特性失败报告。限额沿用旧设计：深度3、成员100MiB、包后代1GiB、5万成员、比例200、单成员120秒、任务展开4GiB |

格式能力按真实样例验收，不因接口存在就宣称全格式完成；未实现适配器应显式 UNSUPPORTED，不回退为原样复制的“成功”。POI、PDFBox、归档组件和字体分发许可随交付清单登记。旧技术方案的 Python 依赖不引入新 Java 服务。

## 7. 文件提交、报告与迁移

输出 `<root>/<taskId>/files`、`report.html`、`exports/`，每任务新目录，原件只读。支持且未命中文档原样复制，整文件失败不复制，范围外不复制。名称脱敏、前缀、非法名称转义和碰撞消歧均记录路径映射，可逆；报告仅异常索引，以输出相对链接定位。

每次尝试在输出根的私有 `.swapy-stage/<taskId>` 写唯一暂存文件，位于公开任务目录之外、与最终目的同一文件系统。校验并强制落盘后，在同一 SQLite 事务登记产物意图、工作结果和实际映射；全部可发布成员准备完成后，以 ATOMIC_MOVE 一次移动完整 files 树，随后对账标记发布。文件系统不支持原子移动则明确失败，不静默跨卷复制冒充原子提交；data 工作缓存不能直接跨卷 move 成为最终产物。启动时对账已登记产物；孤立暂存不当成功输出，网页不暴露私有暂存。扫描可继续，脱敏／还原只收尾已提交产物后中断。SQL 组所有成员通过才登记组就绪；任一成员失败整组不输出，其他格式继续。

正式单包 .swapy 为 ZIP/DEFLATE，manifest、record、mappings、paths；合集外层 STORE，SHA256 校验、路径/数量/实际展开大小限制，不包含原文及主机绝对路径。扩展字段未知可选项保留，核心语义不变；任务包仅可导出稳定就绪脱敏记录，多选／全部按点击时快照。批次完整验证后单事务提交，相同内容重复导入幂等、同任务 ID 不同内容拒绝，扫描／还原包拒绝。

上传还原凭证支持包或完整 JSON，或输入本地任务 ID。本地无记录／不是脱敏任务／库版本不足给明确提示。原型 demo 包只能演示查看，不能直接驱动真实还原。

## 8. API 与前端

保留旧设计 /api/v1 的任务、异常、暂停继续、词库、包、密码本、report 路由；新增 `/roots/{id}/entries?path=` 网页浏览和 `/native-selection` 同机选择。异步操作返回202，参数验证失败4xx，不允许任意绝对路径下载。轮询1秒，服务端状态为准；不使用本机 localStorage 模拟执行。

前端沿用 React17/AntDesign4 的布局与配色，Chrome/Edge80；新服务不自动导入样例任务／样例词库为真实数据。配置与进度在同页，任务历史在独立任务页。首次空库提示导入或添加词条，不能静默拿演示词处理真实文件。

1. SQLite事务、ID、词库历史及批量导入拒绝；持久化重开真实DB验证。

5. REST、包迁移、Git本地发布、浏览器页面与启动／发行脚本；端到端。

## 审查方法

使用未继承作者会话上下文的独立后端审查代理，只读设计、需求规格、词库发布 ADR 和原型交换约定。要求从实施者角度查找会实质改变计划的遗漏、矛盾和核心算法漏洞，不以措辞或一般开发细节充当阻断问题。

## 用户审核项

| 项目 | 建议 |
| --- | --- |
| D1 文件位置与系统选择器 | 首期处理 Docker 主机／挂载共享盘，配薄选择器组件；任意远端本地目录需共享或本地执行代理 |
| D2 四路范围 | 全服务固定四路，三类任务公平共享 |
| D3 英文大小写 | 一词一基础平替，候选字母数相同以逐字母传递大小写，不满足则重选／耗尽跳过 |
| D4 文档区域 | 非正文区域纳入样例验收，PDF 引擎分发与写回能力先验证 |
| D5 无法完整读取的输入 | 整文件不输出、继续其余文件，避重保证明确限于实际完整处理集合 |

这些建议没有写回需求规格为“用户已确认”。用户可以一次性审定或批量修改，不需要重新进行逐题需求访谈。

版本：v1.1  
日期：2026-11-23  
状态：当前需求执行依据；用户已授权完善审核后开发，Java / SQLite 后端正在实施。

本文整合会话首次读取的 `swapy.md` v1.0 与后续需求访谈。已确认决定见 `requirements-decisions.md`，术语见根目录 `CONTEXT.md`。第 13 节汇总最终收口决定及留给设计阶段的细节。

## 1. 产品定位与交付

Swapy 是内网环境下的 B/S 文档脱敏与可逆还原工具，当前采用本地 Java 服务 + SQLite，保留可选 Docker 部署。浏览器提供操作界面，服务端负责文件处理、任务登记、词库和产物管理，敏感词库与平替词库通过内网发布同步。SQLite 数据库位于本机磁盘，原件可在本机或服务可访问的共享盘。

浏览器兼容目标为 Chrome/Edge 80+。界面简洁清晰，采用成熟交互组件，以任务主体内容为中心，不展示辅助说明或执行页最近任务。扫描采用文件浏览器选择文件或文件夹，不采用上传式扫描；B/S 服务端需具备所选位置的读取权限。

最新界面约定：各功能页面和内部窗口铺满可用窗口，移除服务设置。扫描、脱敏、还原独立配置、独立运行，可并行调用；切换页面不停止其他任务。进度条和步骤始终位于对应配置页，不跳转动态分析页面。脱敏、还原均明确提供输入和输出。

并行固定为 4 路，不提供调整项。还原凭证提供上传密码包或输入脱敏任务 ID 两种方式；任务 ID 在本地不存在或本地词库版本低于任务要求时，必须提示并阻止开始还原。

扫描通过文件浏览器选择文件夹，选择后立即开始，展示解析总目标、并行扫描、完成步骤，以及目标总数、已完成数、并行数和暂停／继续。当前 Java 方案默认使用网页内文件浏览器选择已登记根目录，不上传原文；与原型的系统选择器区分。支持断点续扫，暂停、服务重启或断电后沿用原任务号，跳过已完成且未变动文件，继续未完成部分。断点由服务端持久保存，不依赖浏览器存储。

产品按词汇属性选择平替词，维护任务内稳定、一对一的映射，提供扫描、脱敏、文件路径名称处理、历史任务登记、密码包、可视化密码本、还原和失败报告。

所有识别与裁决依赖内置词典、规则、属性映射表和用户填写，不使用大模型。

## 2. 术语与核心关系

| 术语 | 定义 |
| --- | --- |
| 敏感词库 | 收录需要脱敏的原词及其属性的全局单一集合，不按业务分库或分组 |
| 平替词库／脱敏库 | 收录用于平替的词条的集合，与敏感词库分别承担原词识别和平替供给职责 |
| 平替候选池 | 本次任务可考虑的候选集合，来源于平替词库和规则生成 |
| 任务 | 一次针对单文件或文件夹执行的扫描、脱敏或还原操作；脱敏任务生成对应 key 和映射 |
| key | 查找脱敏任务及其映射的还原凭据，不承担加密职责 |
| 注册 ID | 用于文件名任务标注的登记编号，例如 K001，与 key 区分 |
| 任务号 | 一次任务的唯一编号，用于命名独立任务文件夹，与还原 key 区分 |
| 存档 | 任务登记、词库版本依赖、映射及文件处理状态的持久记录 |
| 密码包 | 无损压缩的任务记录与映射迁移载体，不包含源文档，使用时依赖兼容词库 |
| 密码本 | 映射的可读或结构化导出物，格式为离线 HTML 和完整 JSON |
| 弃用 | 词条退出新任务匹配或分配，但保留历史记录供旧任务解释和还原 |
| 部分脱敏 | 文件能正常生成，但仍有已命中、未替换的敏感词 |
| 未扫描 | 因加密、不支持、损坏、超限等原因没有完成检查；不等于无命中 |

## 3. 词库、属性与版本管理

### 3.1 属性来源和优先级

- 属性维度至少包括词性、语言形态和语义角色。
- 词性包括名词、动词、形容词、副词、专有名词。
- 语言形态包括中文词、英文缩写、中文代号、英文全称、数字代号。
- 语义角色包括人名、地名、机构名、产品名、项目代号。
- 属性来源为用户手填、内置词典和规则识别，优先级固定为：手填 > 词典 > 规则。
- 必要属性仍无法确定时，跳过该词并在所属文件的问题中说明。
- 平替候选应降低与原对象的类型相关性，但必须保持语义类型；人名仍替换成人名，机构名仍替换成机构名，不允许跨类型。
- “降低相关性”不等于要求生僻或怪异词汇，具体选词规则留待设计明确。
- 平替词库内置并可扩充，候选也可由规则生成。

### 3.2 递增和弃用

- 敏感词库、平替词库都递增保留历史，不删除已发布的历史词条。
- 新词条使用新 ID，ID 永不复用。替代旧内容时弃用旧词条、启用不同 ID 的新词条。
- 新增记录不能仅以词面或时间戳生成 ID；不同词、不同创建时间和不同配置部署之间不得冲突。正式发布端通过统一 ID 登记和全局唯一约束，确认登记成功后才发布下发；导入已有词条不重新编号。
- 原型采用加密随机 UUID、历史 ID 防重登记及导入冲突检查；跨设备权威唯一性由正式发布端落实。
- 弃用敏感词不再参与新任务匹配，弃用平替词不再分配给新任务。
- 历史任务仍可引用弃用词条，并按原映射还原。
- 高版本必须兼容低版本的历史词条引用，不通过升级改写历史任务的映射含义。

### 3.3 发布和同步

- 敏感词库和平替词库通过内网 Git 统一维护和发布，形成可比较的递增发布序列。
- 软件同步已发布词库，普通用户无需直接操作 Git。
- 提供词库导入、导出按钮，导出包含敏感库、平替库、版本及弃用状态。导入保留历史 ID，不删除旧词条，不降级；同 ID 对应不同词面或属性时拒绝导入。
- 发布过程须保证历史词条保留、ID 不复用及弃用状态有效；这些属于业务兼容规则，不由 Git 自动保证。
- 使用密码包时，只检查本地词库是否达到包声明的版本下限。过低则提示同步，达到要求即可使用。
- 任务不锁定启动时的词库版本，允许使用后续更新；既有任务映射仍须稳定，不因更新重新分配。
- 密码包版本下限按任务实际引用词条所需的最低兼容版本记录，须覆盖运行期间新增词条，不仅记录任务创建时版本；接收端仍仅比较版本下限。

## 4. 文件范围和格式规则

### 4.1 已纳入范围

| 类别 | 格式或范围 | 处理要求 |
| --- | --- | --- |
| 普通文本 | txt、csv、log、ini、yaml、toml 等原需求文本格式 | 支持扫描、脱敏和还原；各结构化格式的具体边界在设计中明确 |
| Markdown | md | 支持扫描、脱敏和还原，保留 Markdown 标记结构 |
| 文档 | docx、doc、rtf、odt | 保留原格式、段落、表格和样式，允许替换词长度引起自然重排 |
| PDF | 含可提取文本层的 PDF | 仅处理文本层，不 OCR；不能正常写回原格式则失败跳过，不转为纯文本 |
| JSON | 字符串值 | 不替换键名、数值、布尔值、null 等语法内容 |
| XML | 文本、属性值 | 不替换标签名、属性名等结构名称 |
| SQL | 字符串字面量、注释、字段名 | 支持扫描、脱敏和还原；保护 SQL 关键字与表名，字段定义及引用使用一致映射 |
| 压缩包 | ZIP、7Z、RAR | 仅扫描内部支持文档的内容，不脱敏、不还原压缩包 |

不支持的文本区域或无法安全替换的命中项，须说明未处理原因，不作成功替换记录。

### 4.2 Markdown

- 正文、代码块和行内代码均参与敏感词匹配及替换。
- 链接文字和地址中的敏感词均参与替换，保留链接语法。
- 不承诺替换后的代码示例可执行或链接地址可访问。
- 独立源码文件排除规则不适用于 Markdown 内的代码示例。

### 4.3 范围外和边界

- 独立源码文件不处理，包含此前讨论的源码注释和文档字符串处理；SQL 明确保留，不按此规则排除。
- 图片及图片型 PDF 的 OCR 不在范围内。
- 加密压缩包或加密条目不尝试解密，不收集解密密码，标记未扫描并说明原因。
- 普通二进制文件不纳入脱敏和标注；文档是否受支持按格式及可处理文本判断，不能仅按是否二进制编码排除 DOCX 等文档。
- 沿用 v1.0 对 HTML 结构化文本的支持；SQL 明确保留，处理字符串字面量、注释和字段名，保护关键字与表名。无法安全替换的命中项跳过并报告。

## 5. 匹配和映射

### 5.1 匹配规则

- 中文按连续字串匹配，不依赖分词边界。
- 英文匹配不区分大小写，仅匹配完整单词，不匹配其他单词内部的子串。
- 包含重叠时长词优先，整体处理一次，不再替换其内部短词。
- 例如“北京”和“北京大学”都在词库时，原文“北京大学”只按长词处理。
- 扫描词频和脱敏使用相同的重叠处理规则，不重复统计被长词覆盖的短词。
- 数字、下划线、中英文相邻时的英文边界，以及交叉重叠的确定性规则，在设计阶段列出明确样例。

### 5.2 分配约束

- 每次脱敏任务随机分配平替词，不沿用前次任务的映射；随机不代表强制每次结果都不同。
- 同一任务内同词同替、异词异替，一对一且持久化，A、B 均遵守。
- 候选必须属性相容，不能跨语义类型。
- 必须检查本次任务所有原文；候选词若已在任一原文出现，必须重选。
- 不能仅靠低重合概率代替实际任务原文避重。
- 内置候选和规则生成均无法提供合格词时，跳过该敏感词、保留原词，继续其他内容，标明部分脱敏并报告。
- 英文还原须恢复每处原始大小写；大小写不敏感匹配不能丢失该信息。设计须兼顾 A、B、一对一及原始写法保留。

### 5.3 A、B 产出形式

| 模式 | 形式 | 规则 |
| --- | --- | --- |
| A 标记平替 | 平替词附带可识别标记，例如 `林舟〔S001〕` | 默认产出形式；示例不是最终标记格式 |
| B 自然词平替 | 仅平替词，例如 `林舟` | 用户可选，不附加内容识别标记 |

- 一次任务统一选择 A 或 B，不设置文件级混用。
- 还原兼容两种产出形式。
- B 还原按映射全部替换，不逐处确认；用户后续自行写入的同名自然词也会一起还原，接受这一边界。

## 6. 扫描

- 支持单文件及文件夹扫描，文件夹递归子目录。
- 文件浏览器选择扫描目标，不在执行页展示待处理文件清单。
- 提供扫描进度条，支持暂停／继续及跨服务重启、断电后的断点续扫。持久保存任务、已完成文件、问题与执行断点，继续时沿用原任务号，跳过已完成且未变动文件；中断时未提交完成结果的文件重新处理。
- 扫描仅展示命中敏感词、读取失败、未扫描等异常项；正常文件不列出。
- 输出命中文件、命中词和词频，不要求行号或偏移位置。
- 支持增量扫描，跳过未变动文件，仅处理新增或修改文件。
- 词库或匹配规则变化后的重扫由用户手动发起，不自动触发；须能手工重新检查未变动文件。
- 默认排除 Swapy 输出目录，避免反复处理输出。

### 6.1 压缩包内容扫描

- 支持 ZIP、7Z、RAR，读取内部支持文档的文本内容，而不仅列出清单。
- 支持嵌套压缩包递归扫描。
- 结果通过“外层压缩包路径 → 内层路径 → 文档路径”定位，并统计命中词与词频。
- 展开深度及总展开大小由软件参数限制，具体数值留给设计。
- 超限部分跳过，继续其他文件；报告未扫描内容和原因，任务标记扫描不完整。
- 不支持格式、加密和其他读取失败均明确说明未扫描原因，不把未扫描视作无命中。

## 7. 脱敏输出、名称和标注

### 7.1 独立输出

- 保留输入文件，脱敏结果写入独立输出目录，不原地覆盖。
- 每次任务在输出根目录下新建以任务号命名的文件夹，不复用既有任务目录。扫描、脱敏、还原均按任务隔离产物。
- 本任务的输出文档、结果报告以及按需生成的密码包和密码本，统一归集到该任务文件夹。
- 保持相对子目录层级；目录名称本身有敏感词时按名称映射替换。
- 能正常处理但未命中敏感词的支持文件，内容原样复制，不计为失败。
- 可正常生成的部分脱敏文件照常输出，未替换问题记入报告。
- 整文件失败不输出原样副本，报告文件和原因，并继续其他文件。
- 图片、独立源码、压缩包及其他不参与脱敏的范围外文件，不随脱敏输出复制；SQL 为明确纳入的例外，压缩包仅参与扫描。
- 可识别的已脱敏文件默认跳过并在报告说明，避免叠加脱敏。

### 7.2 名称替换与任务标注

- 文件名、目录名中的敏感词也参与脱敏，保存名称映射供还原。
- 名称替换与任务前缀标注是不同功能。
- 任务前缀形如 `[swapy-K001]原文件名.ext`，默认开启，可关闭。
- 支持文件中未命中、原样复制的文件也添加前缀，用户关闭标注时除外。
- 前缀可识别、可剥离、幂等，不重复叠加。
- 关闭前缀后，仍能凭系统登记的源文件标识或还原 key 找回对应任务记录。
- 二进制范围外文件不标注。

## 8. 登记、key 和任务状态

- 一次脱敏任务一个 key，单文件与文件夹批量均适用。
- 每次任务分配唯一任务号，作为本次新建任务目录的名称，不以旧目录覆盖方式执行新任务。
- 至少登记源文件名或路径、源文件标识、生成文件 ID、key、注册 ID、词库版本依赖、映射表引用和文件状态。
- 映射与文件输出状态持久保留，作为密码包、密码本和还原的依据。
- 任务中断时，保留已完成文件及对应映射，任务标记中断。
- 扫描支持断点续扫，暂停、服务重启或断电后沿用原任务号及持久记录继续；用户主动暂停的任务不得自动继续。脱敏、还原中断时保留已完成产物、映射和问题，重新执行创建新任务，当前不扩展为跨重启续跑。
- 部分脱敏、整文件失败、扫描不完整、中断分别表达处理状态，不把失败或未扫描文件算作成功。
- 源文件标识和生成文件 ID 的具体编码属于设计项，不把文件名前缀当作全部还原记录。

## 9. 密码包、密码本和失败报告

### 9.1 密码包

- 统一承担跨设备任务记录迁移，包含该任务还原及解出密码本所需的任务记录、映射和版本信息。
- 任务页提供脱敏任务导入、导出；仅脱敏任务可生成任务密码包，扫描、还原任务不得作为任务密码包导出。
- 支持多选脱敏任务一键导出，以及本地全部可导出脱敏密码包一键导出；进行中的脱敏任务尚未形成完整密码包，不列入可导出集合。
- 批量合集导入应全部验证类型和 ID 冲突后提交；重复导入相同记录幂等，同任务 ID 对应不同记录拒绝覆盖。
- 不携带源文档；用户另行准备待还原文档。
- 无损压缩，支持跨设备解算；可据此生成可读密码本。
- 使用时检查兼容词库版本下限；不足时提示同步，不要求逐条核验词条。
- 具体映射编码、压缩算法和包格式另作设计，不承诺固定压缩率。
- 密码包采用稳定的核心记录接口及可扩展约定：保留还原所需的核心语义，高版本兼容低版本，新增可选字段可被旧端忽略，常规扩展不造成任务记录无法读取。
- 接口兼容由设计保证，不将“新版密码包一律拒绝、要求升级”作为常规演进策略；词库版本下限检查仍独立执行。

### 9.2 密码本

- 可单独导出某个 key 对应的映射。
- 提供离线 HTML 可视化密码本与完整 JSON，映射内容一致。
- 成功替换的映射通过密码本展示，不重复列入失败报告。
- 完整 JSON 已携带原词和平替映射时，可加待还原文档独立使用，不强制同步词库或迁移原系统登记。
- 上述 JSON 独立能力与精简密码包的词库依赖分别成立；不能假定只有词条 ID 的包也具备自包含能力。

### 9.3 结果报告、文件索引与失败问题

- 每任务一份 HTML 结果报告，位于以任务号命名的任务目录中，包含任务文件索引和失败问题明细。
- 报告文件索引仅覆盖异常项，提供文件标识、源相对路径、实际输出相对路径及处理状态；正常文件不单列，有输出的异常项提供相对链接，没有输出的失败项列明原因。
- 相对链接用于在整体移动任务目录后继续定位任务输出。
- 异常明细记录扫描敏感词命中、失败、跳过和未完成检查等问题，精确到文件，包含命中词与词频、未替换词或失败原因；不列成功替换映射，成功映射仍归密码本。
- 压缩包内问题定位到具体内部路径。
- 无失败问题时仍遵守“一任务一报告”，报告说明无失败问题，不产生成功映射明细。
- 无需行号、偏移等位置级报告。

## 10. 还原

- 可凭 key 查询存档映射，或通过密码包及兼容词库获取任务信息；完整 JSON 也可提供自包含映射。
- 允许脱敏文档后续编辑。是否可还原依赖映射命中，不用文件 hash 相等作为还原门槛。
- hash 是否用于增量扫描是独立设计问题，不受上一条禁止。
- 支持 A、B 两种形式，B 按映射全部还原，不逐处确认。
- 找不到映射的内容原样保留，不猜测、不因单处未命中而报错终止。
- 允许部分还原：命中内容还原，未命中内容保持现状；标记被删改而无法识别的内容受此边界约束。
- 英文恢复每处原始大小写；文件名和目录名按名称映射还原。
- 还原结果独立输出，保留输入的脱敏文件，不原地覆盖。

## 11. 典型流程

1. 从内网同步词库发布版，新增或替代词条通过统一维护发布流程生效。
2. 选择文件或文件夹扫描，必要时手工重扫；压缩包只参与扫描。
3. 查看文件级命中、词频和未扫描问题。
4. 创建脱敏任务，选择 A 或 B，默认 A。
5. 按属性、原文避重和一对一约束随机分配并持久记录映射。
6. 独立输出文档和名称变更，默认添加任务前缀。
7. 生成任务失败报告；按需导出密码本及密码包。
8. 跨设备传递密码包和另备的文档；接收设备版本不足时同步词库。
9. 解出可读密码本或执行还原，结果另存。

## 12. 验收场景

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AC01 | 同一任务多文件重复出现同一敏感词 | 使用相同平替词 |
| AC02 | 多个不同敏感词 | 平替词互不相同，映射可唯一反查 |
| AC03 | 候选词在另一输入文件原文中出现 | 重选候选，不采用该词 |
| AC04 | 属性不明或无合格候选 | 跳过该词，文件可生成则输出部分脱敏，失败报告说明 |
| AC05 | 单文件无法读取或写出 | 继续其他文件，不输出该文件的原样副本，失败报告说明 |
| AC06 | 支持文件没有敏感词 | 内容原样复制，按任务标注设置添加前缀，不计失败 |
| AC07 | 北京与北京大学同时登记 | 长词优先，不重复替换及计数 |
| AC08 | 英文大小写变体、其他单词内部子串 | 大小写变体命中，内部子串不命中，还原保留原始大小写 |
| AC09 | 中文词出现在更长未登记字串中 | 连续字串命中，不要求分词边界 |
| AC10 | 旧词弃用后用新库还原历史任务 | 旧 ID 仍可引用，按历史映射还原 |
| AC11 | 用密码包但本地词库版本过低 | 提示同步；达到所需下限后可用 |
| AC12 | 编辑 B 文档时新增与平替词同名的词 | 按映射全部还原，包含新增同名词 |
| AC13 | Markdown 代码内容和链接地址含敏感词 | 均替换，保留 Markdown 标记结构 |
| AC14 | JSON 键名和字符串值、XML 标签和文本均含敏感词 | 只处理已约定的数据位置，保护结构名称 |
| AC15 | 嵌套包内有命中文档 | 递归扫描，结果带完整内部路径、词和词频 |
| AC16 | 加密条目或展开超限 | 跳过相关部分并说明，不能记作无命中；超限任务标记扫描不完整 |
| AC17 | 输入目录包含输出目录或已脱敏文件 | 默认排除输出目录，已识别脱敏文件跳过并说明 |
| AC18 | 名称含敏感词、标注关闭 | 名称仍脱敏，凭登记标识或 key 找回，还原名称 |
| AC19 | 用户中断脱敏或还原任务 | 已完成文件及映射保留，状态中断，重跑创建新任务 |
| AC20 | 还原已编辑文件 | 不以 hash 不同拒绝；命中内容还原，其余原样保留；结果另存 |
| AC21 | 任务运行中使用了创建后新增的词条 | 密码包版本下限覆盖实际依赖，不能只记录创建版本 |
| AC22 | 输入目录包含图片、源码、压缩包等范围外文件 | 不随脱敏结果复制；SQL 仍按支持文件处理，压缩包仅参与扫描 |
| AC23 | SQL 字符串、注释、字段名、表名及关键字含命中词 | 字符串、注释和字段名按规则替换，字段定义及引用一致，保护表名和关键字；无法安全处理则跳过报告 |
| AC24 | 同一输入执行多次任务 | 每次新建以不同任务号命名的目录，不复用或覆盖上次任务目录 |
| AC25 | 通过结果报告查找异常项 | 仅定位异常文件，不列普通文件；失败项说明原因，不列成功替换映射 |
| AC26 | 整体移动任务目录 | 报告中的输出相对链接仍可定位文件 |
| AC27 | 密码包新增可选字段 | 旧端仍能读取兼容核心记录，不因未识别的可选扩展拒绝导入；词库版本检查独立生效 |
| AC28 | 扫描期间断电或服务重启后继续 | 沿用原任务号和持久化断点，跳过已完成且未变动文件；未提交完成结果的文件重新处理，计数不重复；用户主动暂停的任务等待手动继续 |
| AC29 | 选择扫描目标 | 文件浏览器选择文件或目录，不进入上传流程，执行页无文件清单与最近任务 |

### 13.2 设计阶段明确，不在本次指定实现

- 密码包映射编码、无损压缩算法、包格式、校验方式及压缩率验证。

- 在 A、B 中同时满足稳定映射、一对一及原始英文大小写保留的可验证方案。
- 英文边界样例、非包含关系交叉重叠的确定性优先级。
- 选词相关性降低的固定规则、规则生成候选的持久化方式。
- 文档各文本区域的支持清单、原格式写回验证及格式适配器选择；Q50 提出的页眉页脚、脚注、尾注、批注及文本框范围尚未获得单独确认，不自动视为全部支持。

- HTML 文档文本与标签、脚本等内容的处理边界。
- SQL 方言识别、带引号字段标识符、字段定义与引用的一致替换及语法验证方式。
- 压缩包展开深度、总大小及其他资源限额的具体数值。
- 词库发布格式、同步传输及触发方式、校验和导入流程。
- 源文件标识、生成文件 ID、跨设备注册 ID 冲突及文件路径冲突处理。
